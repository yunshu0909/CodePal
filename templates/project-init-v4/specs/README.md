# specs — 按版本查任务

每个工作单元保留一个任务的计划、设计、需求、测试、验收与证据。先从 `ISSUES.md` 总览找 Issue（详情按号打开 `issues/` 下的单条文件），再从本页进入带版本的目录。

## 单元从哪来

- 装了 dev-workflow 插件时，开工时由插件自动建单元，目录名形如 `v0.1.1-简述/`，每个任务一个版本号。
- 没装插件时手工建：`specs/<版本或功能名>/`，至少放一页 `1-plan.md`（要什么 + 回退办法 + 测试清单）；需要讨论的再加设计、需求、测试用例。
- 小修小补可以不开单元，在 Issue 里留验收点即可。

## 角色边界

- `.md` / `.json` 是给 AI 的事实源；`_review/` 里的 HTML 是给人看的，**AI 默认不读**。
- 做完的单元不再改；后续变化开新单元，在这里登记。
